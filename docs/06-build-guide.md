# 누가일등 — 바이브코딩 가이드 (협업 프로토콜)

## 1. 스택·구조
- **바닐라 JS** (프레임워크 전환 금지). 단일 index.html은 **파일럿까지만** — v0.9에서 ES Module 분리(src/api·features·ui·utils) 예정
- Supabase(Seoul: DB·Realtime·RPC) + Vercel
- **배포 흐름**: 작업 브랜치 push = Preview → 사용자 승인 → main 병합 = 운영. **대회 운영 중 운영 배포 금지**, 긴급 배포는 P0만. push 후 ~2분 내 자동 배포 미확인 시 수동 `vercel --prod` + 보고(표준 대응)
- 도메인: nuga1.vercel.app (nuga1.kr 연결 예정)
- 폴더: `nuga1/` 루트=index.html+지시서·시나리오 문서 / `design/`=목업 HTML / `brand/`=로고 자산 v3 / `docs/feedback/`=스크린샷 피드백 / `docs/`=본 패키지

## 2. 역할 분담 (3자 체계)
- **설계·판단**: 사용자 + 설계 AI 대화 — 요구를 목업·지시서로 확정
- **시공**: Claude Code — 지시서 단위 구현·커밋·푸시·보고
- **검수**: 사용자 실기기 — 화면·터치·현장 감각의 최종 판정

## 3. 차수 프로토콜 (핵심 규율)
1. 한 차수씩: 지시 → 구현 → push → 검증 보고 → 운영자 확인 → 다음
2. **진행 중 차수 명세 동결** — 새 요구는 새 차수로
3. **목업 선행** — 화면 작업은 design/ 목업 확정 후 착수, 지시서에 "기준: 파일명 장면N" 명기
4. 발견 버그: 등급제 — **P0(개인정보 노출·타 대회 데이터 접근·점수 중복/소실·권한 탈취·마감 후 기록 변경·대회 진행 불가) = 차수 무관 즉시 중단·수정 / P1(순위·점수·진행 오류) = 현재 차수보다 우선 / P2(주요 기능) = 다음 수정 차수 / P3(UI·문구) = 백로그**. P2·P3는 기록만, 즉석 수정 금지 (예외: 지금 만드는 기능 내부의 상태 불일치)
5. 시각 디테일은 스크린샷 왕복으로 수렴 (크기·색은 한 번에 정답 없음)
6. 리디자인 지시에는 "기존에서 살아남아야 할 것" 목록 필수 (회귀 방지)
7. 보고 양식: 원인 → 수정 → 검증(재현 시나리오) 건별. 기계로 확인 불가한 항목은 ⚪로 솔직하게

## 5. DB 마이그레이션 절차
Claude Code가 번호 SQL 생성 → **사용자가 Supabase SQL Editor에서 번호 순서대로 실행**(새 snippet, Success 확인, 번호로 저장) → 실행 완료 보고 → 라이브 검증. 실행 실패 시 에러 전문을 Claude Code에 전달. 테스트 대회는 완료 시 삭제 SQL로 정리(결과 메시지 확인 습관)

## 6. 하지 말 것 (통합)
- 마감·확정·수정 3등급·RPC 로직 중복 구현 (반드시 재사용)
- 전화번호 없는 참가자 / anon 직접 테이블 쓰기 재개방
- 옐로우 남용·800+ 굵기·전광판 고정 px·헤더 URL·자동 조편성
- 단계 기억 UI 상태를 "저장값 유지"로 구현 (진입 시 활성 단계 리셋이 기본)
- access_code를 소유자 증명으로 사용 (secret 체계만)
- 두 차수 동시 진행, 목업 없는 화면 신설
- **UI 정합 대조를 코드/부분 단위로 끝내기** (CH32-A 보완5 교훈): "목업 대조 완료" 판정은
  **렌더 대조(화면 단위·전요소)**만 인정 — 카드 하나만 재고 화면 전체를 통과시키지 말 것.
  부분 대조가 불가피하면 보고에 대조 범위를 명시. 새 `<button>`은 UA 기본 크롬(outset
  테두리·회색 배경)이 기기 브라우저에서 노출되므로 외형 리셋(border/background/appearance)
  선언을 확인하고, 전 버튼 스윕(computed style에서 outset/기본 배경 탐지)을 대조에 포함.
